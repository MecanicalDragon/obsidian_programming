При создании за подом закрепляются:
1. **Стеки сети:** Общий IP-адрес, сетевое пространство (Network Namespace) и порты.
2. **Тома (Volumes):** Общие диски для контейнеров внутри Пода.
3. **IPC / UTS namespaces:** Внутренние механизмы межпроцессного взаимодействия.

Сам под управляется специальным служебным контейнером, написанном на Си (**Pause Container** или `pause`) размером ~500 Килобайт. Он стартует первым, и его единственная задача — вызывать системный вызов `pause()`, засыпать и ничего не делать. Это нужно для того, чтобы в случае падения контейнера с приложением избежать создания нового пода и всех связанных с этим накладных расходов. Если контейнер с приложением падает, Pause-контейнер продолжает спокойно спать - сеть и IP-адрес пода не теряются, а новый контейнер с приложением просто запускается внутри старого пода. 
```
[ Kubernetes Pod (IP: 10.244.0.15) ] 
 ├── Pause-контейнер (удерживает IP, порты и Volumes) ──► Живёт ПОСТОЯННО
 └── Основной контейнер с Java (rth.jar)
      ├── Попытка 1: Упал (OOM / Crash)  ──► Kubelet уничтожает только этот контейнер
      └── Попытка 2: Запущен заново      ──► Получает тот же IP-адрес и те же тома!
```

В экосистеме Kubernetes и Prometheus метрика `restart_count` (полное имя в Prometheus: `kube_pod_container_status_restarts_total`) показывает количество перезапусков конкретного контейнера внутри пода с момента его создания. Когда процесс внутри контейнера падает (или его убивают):
1. Kubelet (агент K8s на ноде) замечает остановку процесса.
2. Согласно правилу `restartPolicy` (по умолчанию `Always`), Kubelet уничтожает старый контейнер и запускает новый с тем же образом и конфигурацией.
3. Сам под не пересоздается: его IP-адрес остаётся прежним, заново планировать под на другую ноду не требуется.
4. Значение `restart_count` увеличивается на 1.

То, как Kubelet реагирует на падение контейнера внутри Пода, задается полем `restartPolicy` в манифесте:
- **`Always`** _(default)_: Перезапускает контейнер всегда при его завершении (даже если код выхода `0`).
- **`OnFailure`**: Перезапускает контейнер только если он завершился с ошибкой (код выхода $\neq$ 0).
- **`Never`**: Никогда не перезапускает контейнер. Под просто переходит в статус `Failed`.
